# Branded sharing

Authors can choose **Partilhar com a marca Yamilook** from the publication sharing dialog. Photos and video frames receive the official logo and the server-verified author's display name and handle, burned into the lower part of the image itself, over a subtle contrast gradient. The shared application asset provides the white wordmark and gold stroke, with the same screen blend as the dark application theme. Photos and videos retain their aspect ratio without an added header. Text exports paginate into 1080 × 1350 JPEG cards without truncation. Every output is previewed before a separate native-share tap; a download is available on unsupported browsers. The original-file workflow remains available below.

The `owned-post-media` branding mode validates Auth, the active session, ownership, RLS and moderation before returning text and attribution. The browser checks again after conversion. Export never changes the post audience. The recipient receives a copy and can save or forward it. This does not make pre-existing public storage URLs private.

Video uses pinned Mediabunny 1.65.1 and WebCodecs, loaded only when exporting. Exports always use a regular (non-fragmented), fast-start AVC/AAC MP4; compatible AAC packets are copied, otherwise audio is transcoded. The pinned @mediabunny/aac-encoder 1.65.1 supplies AAC-LC in browsers without a native encoder. No WebM fallback is passed to destination apps. No microphone capture or third-party media upload occurs. A conversion is rejected if its primary audio track is dropped. The completed file is reparsed to validate video, audio and duration before showing the preview.

Video sources use URL range requests with an 8 MiB cache, so the original can exceed 100 MiB. Video output is capped at 48 MiB, with bitrate adjusted to duration and a 40 MiB target budget. Limits: 100 MiB image source, 10-minute video duration, 1280px maximum source-video edge, 30fps output, 24-megapixel photo input, 1600px photo output edge, 30 text cards. Source video resolution may be reduced; this is not lossless video export. Animated GIFs are directed to the original-file workflow rather than flattened. HEIC and other image decoding depend on browser support. A browser without compatible decoders/encoders offers the original-file workflow rather than silently exporting without sound. Keep the page open; cancellation/unmount stops conversion and object URLs are released.

Validation: owner/auth/session/moderation and media-stream Node tests; component tests for preview, fresh user activation, downloading, pagination, cancellation and changed-content rejection; video-unit tests prevent silently discarded audio. CI additionally generates a 3-second AVC/AAC fixture, converts it in Chromium, downloads the actual result, uses ffprobe to inspect tracks/duration and ffmpeg to check audible decoded samples (and identical AAC samples when copied), and retains video/frame artifacts. TypeScript and production build are included in the sharing workflow. Physical iPhone/Android application share sheets require device validation; CI does not claim to simulate those apps.

## Mobile share compatibility fix

A reported Contacts-only source was a 130,886,324-byte, approximately 98-second VP9/Opus WebM without declared duration metadata. The old generic file preparation rejected it at 100 MiB and the download alternative returned that same WebM. The new owner video service validates ownership before range-based conversion and again before releasing the result. Both prepare and download offer the converted MP4, with a playable preview and a fresh native-share tap. The branded path uses the same conversion service and preserves the embedded logo and author. Image handling and publication privacy are unchanged.

Regression coverage includes live WebM without Duration/Cues, a synthetic 125 MiB input, regular MP4 moov/sample tables (no moof fragments), H.264/AAC codec checks, audible audio, timeline duration, authorization revocation and changed media, plus both prepare/download component actions. No private user media is committed to the repository or uploaded as CI artifacts.
